# Feature: Workout sessions

Objective: log what actually happened in a workout — sets with weight, reps and RPE — started from a routine or free. Branch: `feat/workout-sessions` (based on `feat/database-setup`). Delivery: work-unit commits; push/PR are the user's call. Test runner: Vitest (`pnpm test`, `pnpm test:integration` against `gymple_test`).

## Specs

- **S1** — User's words: "Cargas tus ejercicios, cargas tus pesos, que puedas ver cómo evolucionaste en X ejercicio" and "una sesión de entrenamiento sería la \"ejecución\" de una rutina". Also: "podrás setear tiempo de descanso, cantidad de series, incluso tu sensación de esfuerzo."
  - A session belongs to a user, optionally references the routine it was started from, has `startedAt`, `finishedAt` (null while active) and optional notes (max 1000, CRLF counted as one char, empty → null).
  - A logged set: exercise, weight in kg (0–999.99, max 2 decimals; 0 allowed for bodyweight), reps (integer 1–100), optional RPE (1–10 in 0.5 steps), optional rest seconds (integer 0–600). Set numbers are per exercise within the session, starting at 1, assigned by the system.
  - Assumption: kilograms only.
- **S2** — Start: from a routine ("Start" on the routines list and the routine edit page) or a free session (no routine). Assumption: only one active session per user; starting another while one is active is rejected with "Finish or discard your current workout first." and the UI links to the active one.
- **S3** — Active session screen (mobile-first): for a routine session, the routine's exercises in routine order, each showing its targets (sets × reps range, rest) and the sets logged so far; then any extra exercises that have sets. Logging a set prefills weight and reps from the last set of that exercise in this session, else from the most recent finished session that logged it ("Last time: 80 kg × 8"). Any of the user's active exercises can be added to the session (by logging its first set). Sets can be edited and deleted while active.
- **S4** — Finish: sets `finishedAt` and optional notes; a session with zero sets cannot be finished ("Log at least one set before finishing."). Discard: deletes an active session and its sets (with a confirmation step in the UI).
- **S5** — History: `/sessions` lists finished sessions newest first (date, routine name or "Free workout", number of exercises and sets, duration). `/sessions/[id]` shows a finished session's sets grouped by exercise; sets there can still be edited or deleted to fix typos, and the whole session can be deleted (with confirmation).
- **S6** — Ownership (security): every read and write is scoped to the session user; another user's session or set behaves like a missing one. A set may only reference an exercise the user owns (archived allowed only if the exercise already has sets in this session; new sets require an active exercise). Starting from a routine requires the user to own it and it to be active.
- **S7** — Same quality bar as exercises/routines: domain validation tests, use-case tests on an in-memory repository, a shared repository contract suite run on in-memory and MySQL (isolation included), server action tests pinning the session as the only source of the user, every page/action calling `requireUser()`, mutation checks on the ownership filters.
- **S8** — User's words: "en medio de la sesión se podrán cargar más series o nuevos ejercicios. Al terminar la sesión se preguntará si quiere guardar el entrenamiento o si quiere modificar la plantilla con estas nuevas series o ejercicios"
  - Mid-session: more sets than the target and exercises not in the routine can be logged (already covered by S3).
  - On finishing a routine session whose logged work differs from the template by additions, the user chooses "Save workout" (session only) or "Save and update routine" (session + template). If there are no additions, finishing just saves.
  - Assumption — only additions are applied to the template: an exercise not in the routine is appended at the end (in the order first logged) with targetSets = sets logged, reps range = min–max reps logged, rest = rest logged on its sets if any, else 90 s; an exercise already in the routine with more sets logged than its targetSets gets targetSets raised to that count. Fewer sets or skipped exercises never remove anything. When the same exercise appears more than once in the routine, it is planned as the sum of its occurrences; only sets beyond that total are extra, and they are added to its first occurrence.
  - Assumption — free sessions (no routine) only save; an archived or no-longer-owned routine also only saves.
  - The template update and the finish happen together: if the routine update fails validation (e.g. would exceed 50 exercises), nothing is finished and the user sees the reason.
- **Out of scope (follow-ups):** rest timer, progress charts and 1RM history per exercise (next feature, uses `modules/progress`), editing session start time.
